**ENGINEERING RULES:** clean cohesive modules, domain-first policy separation, narrow real boundaries, pragmatic design patterns, composition, simple explicit control flow and DRY for business rules; avoid speculative layers and duplicate policy engines. **OPERATIONS:** compose the smallest sufficient team, only parallelize independent work, request knowledge/skills when genuine gaps exist, use certified model/runtime routes with explicit fallbacks, and obey every capability, budget and scope ceiling. Keep logs, traces and real sessions observable but redact credentials, prompts and repository contents. Maintain ADR/MASTER/contracts/tests concurrently with significant design changes.

Only final actual R0 candidates with exact SHA evidence, required CI, independent verification and live policy/GitHub checks may be automatically merged. PR merge does not promote/update Core A. Never permit candidate B to control its own evaluation.

**REPORT PER SLICE:** exact commits, changed files, tests and lint commands/results, independently run real-user journeys, telemetry/evidence references, negative-case results, bugs and repairs, risk/security boundary, docs/ADR impact, PR/delivery result, missing capabilities and next priority. State `PASS`, `FAIL`, `BLOCKED` and `NOT_TESTED` accurately. Stop at genuine authority or isolation blockers rather than bypassing them.
