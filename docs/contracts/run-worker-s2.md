# Contract: Run–Worker (F1-S2 frozen portion)

**Status:** Agreed for F1-S2. **Version:** `1`. Experimental pre-release
contract; breaking changes require updating all in-repo callers, tests, docs
and fixtures atomically ([ADR-0006](../architecture/decisions/ADR-0006-early-development-compatibility.md)).

S2 covers exactly the slice below. Real provider/agent execution, remote
Workers, per-Worker credentials and Campaign orchestration are deferred.
SEC-01 remains BLOCKED: only the fixed credential-free synthetic workload
below is authorized.

## 1. Identities

| Entity | ID shape | Notes |
| --- | --- | --- |
| Run | 16 random bytes, hex (32 chars) | Generated by Core, never client-supplied |
| Attempt | 16 random bytes, hex (32 chars) | One row per lease grant; retries never rewrite history |
| Worker | operator-chosen slug `[a-z0-9-_]{1,64}`, e.g. `local-1` | Registered by Core; unknown IDs rejected |
| Lease generation | positive int64, Core-owned, monotonic per Run | Fencing token; incremented on every lease grant |

## 2. Run schema (JSON)

```json
{
  "id": "9f…",
  "projectId": "default",
  "actionId": "optional Action id or empty",
  "workloadKind": "synthetic-echo",
  "workloadInput": {"message": "≤256 chars", "steps": "1..10", "stepMs": "0..200"},
  "status": "queued | leased | running | succeeded | failed | cancelled",
  "attemptCount": "number of Attempts granted so far",
  "maxAttempts": "1..5, default 3",
  "timeoutSecs": "5..600, default 120",
  "leaseOwner": "workerId holding the current lease or empty",
  "leaseGeneration": "current fencing generation",
  "leaseExpiresAt": "RFC3339Nano UTC or empty",
  "result": "bounded output object on success or empty",
  "error": "short failure reason or empty",
  "createdAt": "RFC3339Nano UTC",
  "updatedAt": "RFC3339Nano UTC"
}
```

`workloadKind` other than `synthetic-echo` is rejected (`400 invalid`).
`workloadInput` is bounded at the domain boundary (message ≤256 chars,
`steps` 1–10, `stepMs` 0–200, JSON ≤4 KiB). Only explicitly listed keys are
accepted; unknown keys are rejected.

## 3. Attempt schema (JSON)

```json
{
  "id": "ab…",
  "runId": "9f…",
  "seq": "1-based per Run",
  "workerId": "local-1",
  "leaseGeneration": "generation granted with this Attempt",
  "status": "leased | running | succeeded | failed | expired | cancelled",
  "heartbeats": "count of accepted renewals",
  "result": "bounded output or empty",
  "error": "short reason or empty",
  "createdAt": "RFC3339Nano UTC",
  "updatedAt": "RFC3339Nano UTC"
}
```

## 4. Run lifecycle (complete S2 state machine)

```text
queued → leased → running → succeeded
queued → leased → running → failed → queued (retry, seq+1, generation+1)
queued → cancelled | leased → cancelled | running → cancelled
leased → queued (lease expiry, retry) | leased → failed (retry exhausted)
running → queued (lease expiry, retry) | running → failed (retry exhausted)
running → failed (timeout or reported failure)
```

`succeeded`, `failed` (after exhaustion) and `cancelled` are terminal.
`failed → queued` exists only while `attemptCount < maxAttempts`.
A finished Run never changes its associated Action's status.
Terminal Runs carry no lease: `leaseOwner` is cleared on every terminal
transition.

- A Run is **queued** when Core accepts the operator request.
- A Worker obtains a **lease** when Core grants an Attempt
  (`leaseOwner`, `leaseGeneration`, `leaseExpiresAt` set atomically).
- Execution **starts** when the Worker reports the first heartbeat;
  Core moves Attempt `leased → running` and Run `leased → running`.
- A **heartbeat** renews `leaseExpiresAt` (no durable event per heartbeat;
  only transitions emit events).
- Execution **succeeds/fails** when Core accepts a matching report.
- An attempt **expires** when the sweeper finds
  `now ≥ leaseExpiresAt` on a non-terminal Run.
- **Retries** are permitted while `attemptCount < maxAttempts`.
- **Cancellation** is effective when Core records it; late Worker messages
  for the Run are rejected as stale.
- The **authoritative outcome** is the terminal Run row plus its events.

## 5. Core–Worker protocol

Operator routes require `Authorization: Bearer <FACTORY_API_TOKEN>`.
Worker routes require `Authorization: Bearer <FACTORY_WORKER_TOKEN>` and
reject the operator token. The worker token never grants operator access.

| Method | Route | Auth | Meaning |
| --- | --- | --- | --- |
| POST | `/api/v1/runs` | operator | Queue a synthetic Run (`201`) |
| GET | `/api/v1/runs` | operator | List Runs, newest first (`status`, `limit`) |
| GET | `/api/v1/runs/{id}` | operator | One Run |
| GET | `/api/v1/runs/{id}/attempts` | operator | Attempt history, `seq` order |
| POST | `/api/v1/runs/{id}/cancel` | operator | Cancel a non-terminal Run |
| GET | `/api/v1/workers` | operator | Worker snapshots (liveness, no fabricated activity) |
| GET | `/api/v1/workers/{id}` | operator | One Worker |
| POST | `/api/v1/workers/register` | worker | `{workerId, version}`; idempotent by `workerId` |
| POST | `/api/v1/workers/poll` | worker | `{workerId}`; grants one lease (`200`) or no work (`204`); an empty poll still records Worker liveness |
| POST | `/api/v1/workers/heartbeat` | worker | `{workerId, runId, attemptId, generation}`; renews lease |
| POST | `/api/v1/workers/report` | worker | `{workerId, runId, attemptId, generation, outcome, output?, error?}` |

`outcome` is `completed | failed`. Every Worker message is traceable via
`workerId`, `runId`, `attemptId`, `generation` and `X-Correlation-ID`.

## 6. Lease fencing and idempotency

Core rejects (no state change, no new event) and the Worker must treat as
terminal for that Attempt:

- unknown Worker (`404 not_found`), unknown Run/Attempt (`404 not_found`);
  a cancelled Run is checked before Attempt existence, so any Worker
  message for a cancelled Run is `409 run_cancelled` even when the
  Attempt identity is unknown;
- report for an Attempt that never started (`409 not_started` — the
  lifecycle is `leased → running → succeeded/failed`; the first heartbeat
  is what starts execution);
- generation mismatch (`409 stale_generation`);
- report/heartbeat after expiry (`409 lease_expired`);
- any Worker message after cancellation (`409 run_cancelled`);
- duplicate delivery of an already-recorded report with identical
  `(attemptId, generation, outcome)` is an idempotent replay (`200 OK`,
  `Idempotent-Replayed: true`, no new event, no duplicated effect).

For the synthetic workload, the authoritative effect is the terminal Run
row plus its receipt; the Worker writes its artifact receipt carrying
`(runId, attemptId, generation)` so a duplicated artifact is detectable and
never promoted to a second authoritative result.

## 7. Worker and execution boundary

One real Rust Worker process (`factory-worker`): registration, bounded
poll loop (`--max-concurrent`, default 1), heartbeat goroutine,
context-aware cancellation, clean shutdown, structured result reporting.

The workload executes in a disposable fixture:

- Preferred: rootless Podman, `alpine:3.20`, `--network=none`,
  `--read-only`, `--cap-drop=ALL`, `--security-opt=no-new-privileges`,
  `--pids-limit=32`, `--memory=128m`, writable disposable `/workspace`
  only, minimal environment, no HOME/auth/socket mounts. This is the
  default (`--exec-mode podman`) and fails closed: without a working
  Podman or the fixture image the Worker refuses to start rather than
  downgrading.
- Explicit fallback: pure-Go in-process fixture (no shell, no subprocess)
  selected only via `--exec-mode local` for appropriate tests and
  development; the effective mode is always reported in the result,
  the Worker startup log and the attempt receipt.

Forbidden: `--privileged`, host HOME/auth mounts, container-socket
mounts, host networking, arbitrary commands, real provider credentials.
Podman failure is reported as failure, never converted into success.

## 8. Recovery rules

- Worker crash/disconnect: lease expires → Attempt `expired`, Run requeued
  or `failed` on exhaustion; a restarted Worker polls and receives new
  work with a new generation. A stale completion for the old generation
  is rejected.
- Core restart: on boot, non-terminal leased/running Runs reconcile to
  `expired` Attempts and requeued/`failed` Runs; Workers start `offline`
  until they re-register. History survives; nothing unfinished disappears
  silently.
- Lost heartbeat, repeated delivery, delayed stale completion, cancel
  racing completion, and retry exhaustion all follow §6: exactly one
  authoritative terminal outcome per Run.

## 9. Events (S2 additions, schema version `1`)

`RunQueued`, `RunLeased`, `RunStarted`, `RunCompleted`, `RunFailed`,
`RunExpired`, `RunCancelled`, `WorkerRegistered`, `WorkerOffline`.
Aggregates `run/<runId>` (per-Run sequence) and `worker/<workerId>`.
Heartbeat renewals update the snapshot only; transitions emit events.
Payloads carry `runId`, `attemptId`, `generation`, `workerId`, bounded
`reason`/`output` — never tokens, credentials or source bodies.

## 10. S2 acceptance (binding)

- Submit → `queued` → lease granted → real execution → reported result →
  authoritative terminal Run, all observed via API and Factory Office;
  restart retains Runs, Attempts, Workers and full event history.
- Crash/restart/fencing probes: kill the Worker mid-Attempt and prove
  expiry, bounded retry, stale-generation rejection and no duplicated
  authoritative effect.
- Every negative in §5–§6 is exercised over real HTTP; Podman fixture
  restrictions are probed (forbidden paths/network/mounts inaccessible);
  S1 journeys (`scripts/e2e-s1.sh`) still pass unmodified.
