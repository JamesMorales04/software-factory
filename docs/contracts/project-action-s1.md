# Contract: Project–Action (S1 frozen portion)

**Status:** Agreed for F1-S1. **Version:** `1`. Experimental pre-release contract;
breaking changes require updating all in-repo callers, tests, docs and
fixtures atomically ([ADR-0006](../architecture/decisions/ADR-0006-early-development-compatibility.md)).

S1 covers exactly the slice below. Campaign–Run, Core–Worker, Agent Session
and Quality–Delivery contracts evolve in later slices.

## 1. Identities

| Entity | ID shape | Notes |
|---|---|---|
| Project | slug `[a-z0-9-_]{1,64}`, e.g. `default` | Seeded `default` project always exists |
| Action | 16 random bytes, hex (32 chars) | Generated by Core, never client-supplied |
| Idempotency key | opaque client string, UNIQUE when present | Replays return the original Action |

## 2. Action schema (JSON)

```json
{
  "id": "9f…",
  "projectId": "default",
  "title": "≤200 chars, required, trimmed",
  "description": "≤2000 chars, optional",
  "status": "pending | in_progress | completed | cancelled",
  "idempotencyKey": "opaque, echoed when supplied",
  "createdAt": "RFC3339Nano UTC",
  "updatedAt": "RFC3339Nano UTC"
}
```

Create request: `{projectId?, title, description?}`. Unknown fields are
rejected (`400 invalid`). `projectId` defaults to `default`; unknown projects
are rejected (`400 invalid`).

## 3. Lifecycle (complete S1 state machine)

```text
pending → in_progress → completed
pending → cancelled
in_progress → cancelled
```

`completed` and `cancelled` are terminal. Any other edge, including
`pending → completed`, is rejected with `409 conflict`. Unknown status
strings are rejected with `400 invalid`.

## 4. Authorization

All `/api/v1/*` routes require `Authorization: Bearer <FACTORY_API_TOKEN>`.
Missing or wrong tokens get `401 unauthorized` with no further information.
The token is configured via environment, never logged, and redacted from
telemetry (see telemetry contract).

## 5. Idempotency

`POST /api/v1/actions` accepts `Idempotency-Key`. The first request with a
key persists the Action; a repeat with the same key returns `200 OK`, the
original Action, header `Idempotent-Replayed: true`, and records **no** new
Action or event. Keys are global.

## 6. Errors (stable codes)

| HTTP | code | Meaning |
|---|---|---|
| 400 | `invalid` | validation, malformed JSON, unknown field/status |
| 401 | `unauthorized` | missing/wrong Bearer token |
| 404 | `not_found` | unknown Action id |
| 409 | `conflict` | illegal state transition |
| 500 | `internal` | storage/telemetry failure (never leaks internals) |

Shape: `{"error":{"code":"…","message":"…"}}`.

## 7. S1 acceptance (binding)

- Create → list → detail round-trips through the real HTTP API.
- Duplicate idempotency key creates exactly one Action and one event.
- Legal/illegal transitions behave per §3, verified over HTTP.
- Restart retains every Action and its ledger (see Factory Events S1).
- Every negative row in §4–§6 is exercised by `scripts/e2e-s1.sh`.
