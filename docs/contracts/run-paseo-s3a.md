# Contract: Run–Paseo session identity (F1-S3-A)

**Status:** Agreed for F1-S3-A. **Version:** `1`. Experimental pre-release
contract; breaking changes require updating all in-repo callers, tests, docs
and fixtures atomically ([ADR-0006](../architecture/decisions/ADR-0006-early-development-compatibility.md)).

S3-A covers exactly the slice below: durable execution configuration and
session identity for real Paseo workloads. Real session start/observe/stop
(Worker → Paseo), Office timeline projection, and the full
cancel/recovery matrix are deferred to S3-B/S3-C/S3-D. No Paseo session is
started by this slice; no paid provider call is required to verify it.

This contract does not amend the frozen S2 contract: `run-worker-s2.md` v1
keeps its credential-free synthetic semantics unchanged. S2 behavior is a
regression gate for S3-A, not a migration source.

## 1. Identities

| Entity | ID shape | Notes |
| --- | --- | --- |
| Run | 16 random bytes, hex (32 chars) | Generated by Core, never client-supplied (unchanged from S2) |
| Attempt | 16 random bytes, hex (32 chars) | One row per lease grant; retries never rewrite history (unchanged) |
| Worker | operator-chosen slug `[a-z0-9-_]{1,64}` | Registered by Core; unknown IDs rejected (unchanged) |
| Lease generation | positive int64, Core-owned, monotonic per Run | Fencing token; incremented on every lease grant (unchanged) |
| Paseo workspace | opaque Paseo token, `1..128` chars, `[A-Za-z0-9\-_:.]` | Asserted from session evidence in S3-B; stored opaquely in S3-A |
| Paseo session (agent) | opaque Paseo token, `1..128` chars, `[A-Za-z0-9\-_:.]` | Real agent IDs are UUIDs; asserted from `paseo inspect` in S3-B |
| Session binding | keyed by `(attemptId)`; unique per generation | Exactly one binding row per Attempt; terminal rows immutable |

The binding is the durable 1:1 link between one Attempt generation and one
real Paseo session. A new Attempt (retry, new generation) gets a new
binding; an old binding never changes identity.

## 2. Execution modes and routing

| Mode | Value | Meaning |
| --- | --- | --- |
| `restricted` | default | S2 credential-free synthetic fixture. No provider/model, no session. |
| `trusted-local` | explicit | Owner-authorized local execution with broad host access per [ADR-0009](../architecture/decisions/ADR-0009-trusted-local-execution.md) and the [trusted-local policy](../security/trusted-local.md). Never labeled isolated, sandboxed, certified, or SEC-01 PASS. |

There is no `isolated` value in S3-A. Isolated execution keeps its separate
certification path and is rejected at the domain boundary.

Only three exact provider/model/mode triples are authorized in S3, matching
the smoke-proven routes in `docs/security/paseo-readiness.md`:

| Provider | Model | Mode |
| --- | --- | --- |
| `codex` | `gpt-6-luna` | `full-access` |
| `opencode` | `opencode-go/muse-spark-1.3-contributor` | `build` |
| `opencode` | `opencode-go/deepseek-v4.1-flash` | `build` |

Rules (all enforced at the domain boundary, never in handlers or storage):

- `synthetic-echo` requires `restricted` and forbids provider/model/mode.
- `paseo-task` requires `trusted-local` and an exact allowlist triple.
- Matching is exact and case-sensitive after trimming; a pinned model with
  an empty effective model, or any substitution (different mode for the
  same model, same model under a different provider, unlisted Copilot-backed
  routes), is a hard `400 invalid` failure — never a silent fallback.
- The task text lives in `workloadInput.task` only (`1..2000` chars,
  `workloadInput` JSON ≤4 KiB, no other keys). Routing lives in top-level
  Run fields so it stays queryable and fenced.

## 3. Run schema additions (S3-A)

S2 fields are unchanged. New fields:

```json
{
  "executionMode": "restricted | trusted-local",
  "provider": "codex | opencode (paseo-task only)",
  "model": "exact allowlist model (paseo-task only)",
  "paseoMode": "exact allowlist mode (paseo-task only)"
}
```

`executionMode` defaults to `restricted` when omitted. Synthetic runs
persist empty routing; paseo-task runs persist the frozen requested routing
for the Run's lifetime (no update path exists).

  "status": "intended | active | succeeded | failed | cancelled | orphaned",

  "updatedAt": "RFC3339Nano UTC"

## 5. Binding lifecycle

```text
intended → active → succeeded
intended → active → failed
intended → active → cancelled
intended → failed        (startup failure before any session existed)
intended → cancelled     (cancel before any Paseo call completed)
intended|active → orphaned   (generation superseded while a session may exist)
```

`succeeded`, `failed`, `cancelled` and `orphaned` are terminal and
immutable. `orphaned` means a Paseo session may still exist externally but
its generation is superseded: it is recorded honestly for cleanup and can
never become authoritative. Cancellation of the Run cancels a non-terminal
binding in the same transaction. Expiry, timeout, and Core-restart
reconciliation orphan a non-terminal binding in the same transaction.

Binding requires the Attempt to have started (`leased → running` via
heartbeat, the S2 rule); intend is valid in `leased` or `running`. Reports
for the Attempt lifecycle are unchanged from S2.

Ordering rule for S3-B: the Worker closes the session binding **before**
reporting the Attempt. A report that lands first makes the Run terminal;
a forgotten `active` binding on a terminal Run is then fenced (`409
stale_generation`) and stays `active` as evidence of the ordering
violation — it is never closed retroactively and never becomes
authoritative.

## 6. Intend-before-create and crash semantics

SQLite and Paseo never participate in one atomic transaction. Instead:

1. The Worker persists **intent** (`intended`, no external call yet) and
   receives the frozen routing for the generation.
2. The Worker performs the non-idempotent Paseo calls (workspace create,
   session start — S3-B).
3. The Worker **binds** the proven workspace/session identity.
4. The Worker **closes** the binding with the terminal observation.

Crash accounting:

- Crash between (1) and (3): an `intended` row with no session exists.
  Expiry/restart reconciliation orphans it; S3-B re-binds or archives the
  external session by label and retries with a new generation.
- Crash after (3) with an `active` row: the binding survives restarts
  (durable row + events); S3-B re-attaches by session id.
- Crash between a Paseo call and (3): the external session exists without
  a bound identity. It is discoverable by the `(runId, attemptId,
  generation)` label convention (S3-B) and recorded as `orphaned`, never
  silently adopted by another generation.
- Where a session cannot be proved stopped, its binding stays `orphaned`
  with the reason recorded. Exactly-once external side effects are never
  claimed on Core fencing alone.

## 7. Protocol (S3-A additions)

Operator routes require `Authorization: Bearer <FACTORY_API_TOKEN>`.
Worker routes require `Authorization: Bearer <FACTORY_WORKER_TOKEN>` and
reject the operator token.

| Method | Route | Auth | Meaning |
| --- | --- | --- | --- |
| POST | `/api/v1/runs` | operator | Extended: accepts `executionMode`, `provider`, `model`, `paseoMode` |
| GET | `/api/v1/runs/{id}/sessions` | operator | Session bindings for one Run, `seq` order (`404` unknown Run) |
| POST | `/api/v1/workers/session/intend` | worker | `{workerId, runId, attemptId, generation}` → `201` or idempotent replay |
| POST | `/api/v1/workers/session/bind` | worker | `{…, workspaceId, sessionId}` → `200` or idempotent replay |
| POST | `/api/v1/workers/session/close` | worker | `{…, outcome: succeeded\|failed\|cancelled, error?}` → `200` or replay |
| POST | `/api/v1/workers/session/orphan` | worker | `{…, reason?}` → records unprovable session honestly |

Fencing (no state change, no new event; stale Attempts abandon without
reporting — same narrow codes as S2 §6):

- unknown Worker/Run/Attempt → `404 not_found`; cancelled Run short-circuits
  to `409 run_cancelled` even for unknown Attempt identities;
- unknown generation → `409 stale_generation`;
- intend/bind/close/orphan after expiry → `409 lease_expired`;
- bind before the first heartbeat → `409 not_started`;
- bind without intend, succeed-without-bind → `400 invalid`;
- duplicate delivery with identical identity/outcome → `200 OK`,
  `Idempotent-Replayed: true`, no new event;
- conflicting re-bind or conflicting close on a terminal row →
  `409 stale_generation`.

## 8. Events (S3-A additions, schema version `1`)

`PaseoSessionIntended`, `PaseoSessionActive`, `PaseoSessionSucceeded`,
`PaseoSessionFailed`, `PaseoSessionCancelled`, `PaseoSessionOrphaned`.
All on aggregate `run/<runId>` with the existing per-aggregate sequence and
global replay transport — no second ledger. Payloads carry IDs, routing,
and bounded `reason`/`error` only: never tokens, credentials, prompt bodies,
or source. Heartbeat-style renewals emit no events; only transitions do.

## 9. S3-A acceptance (binding)

- Queue a `paseo-task` trusted-local Run for each allowlisted route; every
  substitution, mode swap, unlisted route, and malformed task is `400`.
- Intend → bind (fake opaque IDs, no Paseo) → close succeeds over real
  HTTP; duplicate deliveries replay with no new events; stale generations,
  expired leases, cancel races, and unknown identities are fenced per §7.
- Expiry, timeout, Core restart, and Run cancellation orphan or cancel the
  live binding in the same transaction; the orphaned generation can never
  report authoritatively.
- Restart retains Runs, Attempts, bindings, Workers, and full event
  history including the six new event types.
- S1 journeys and the S2 suite (unit, fencing, e2e, browser) still pass
  unmodified in behavior: synthetic runs carry `restricted` with empty
  routing, and no synthetic row gains a binding.
- No real Paseo session is started to verify this slice; the Worker does
  not execute paseo-task Runs in S3-A (real lifecycle is S3-B).
