# Service placement assessment: optional Tailscale Serve node

| Field | Assessment |
|---|---|
| **Component** | Optional `tailscale` Compose service |
| **Responsibility** | Maintain one Tailscale node identity and privately proxy HTTPS Office traffic to Core's restricted Office listener through a dedicated Unix domain socket. It does not authenticate Factory users, make authorization decisions, or own Factory state. |
| **Proposed owner** | Deployment infrastructure; Core remains application authority. |
| **Trust classification** | Trusted infrastructure under `TRUSTED_LOCAL`; packaging does not certify isolation. |
| **Authority and credentials** | The node's private Tailscale identity key is persisted in the dedicated `factory-tailscale-state` volume. First enrollment is an interactive login URL; no auth key, Core/provider token or service secret is supplied through Compose. The volume is sensitive and must be protected by the local Podman account. |
| **Untrusted execution exposure** | No code execution. It parses untrusted network traffic and proxies HTTP requests to Core. |
| **Selected placement** | LEVEL C persistent container, opt-in overlay only. It requires a stable Tailscale node identity and its own network namespace/lifecycle. |
| **Alternatives considered** | Host-installed Tailscale would violate the no-host-runtime target. Host networking/TUN and `NET_ADMIN` add unnecessary privileges. Joining control/egress networks exposes unrelated Factory peers. A public reverse proxy or port forwarding violates private-only access. |
| **Reasons for selection** | A dedicated official client container supplies outbound tailnet connectivity and HTTPS Serve while userspace mode avoids `/dev/net/tun` and extra capabilities. |
| **Container/Pod/network boundaries** | The service joins only `factory-tailscale-uplink` (external egress, Tailscale only). It shares no network with Core and is absent from `factory-control`, `factory-egress` and every Core interface, so it cannot reach the full Core API on 8765 by address or service name. The restricted Office listener is a Unix domain socket in the dedicated `factory-office-socket` volume, mounted read-only in Tailscale. Core's full control listener binds only the `core-control` and `core-egress` aliases. Core retains only its existing loopback host port for local recovery; the restricted Office socket is not host-published. The Office listener explicitly omits Worker, Supervisor, verifier, reviewer and Quality Gate role/control routes. Tailscale publishes no host port. Serve exposes HTTPS 443 privately to the tailnet; Funnel is explicitly false. The image is pinned to the verified v1.104.4 multi-architecture digest because official bulletins TS-2026-016/017 affect Unix-backed Serve behavior on earlier releases. |
| **Filesystem and secret access** | Root filesystem read-only; tmpfs only for runtime files; one named writable node-state volume; one read-only Office socket volume; one read-only bind to the static Serve configuration. The socket grants only the restricted Office router, not control authority. No host HOME, runtime socket, Core data/config, provider secrets or other service config. Node identity state is a credential and is not included in logs or evidence. |
| **Lifecycle and failure behavior** | `unless-stopped`; node identity persists across restart. Tailscale control-plane or DERP failure removes remote availability; Core remains local when the overlay is disabled. Removal of the state volume revokes continuity and requires new enrollment. Core cannot probe Tailscale health without a shared network, so Access & Devices reports `CONFIGURED` rather than claiming a live path. |
| **Resource constraints** | CPU is limited to 0.5, memory to 256 MiB and process count to 128. Persistent state-volume quota is not configured. Outbound Tailscale control/DERP traffic is required and is not destination-pinned. These are open hardening items. |
| **Persistent state ownership** | Tailscale container exclusively writes its node state volume. It is separate from all Factory volumes. No Factory migration or deletion path touches it. |
| **Remote Worker implications** | None. The service is an Office access path and does not enroll, dispatch or authorize Workers. |
| **Required tests** | Static policy negatives for capabilities, devices, host ports, auth material, network membership, listener aliases, socket mounts and bind placement; real rootless Podman boot/login; HTTPS Serve to the Unix socket; node identity persistence after restart; a real Podman probe from the Tailscale container proving Core's control and egress addresses are unreachable and no TCP Office listener exists; socket reachability/permissions; verify no public Funnel; cross-network mobile access; cleanup/revocation. |
| **Known risks** | HTTPS certificate consent may require tailnet admin action; the persistent state volume has no quota and outbound destinations are not pinned. A compromised node can reach the restricted Office socket but not the full control listener or any other Core port, and cannot bypass Core sessions. The socket volume itself is a shared boundary and must remain mounted only in Core, Tailscale and the initialization job. |
