## Status vocabulary

| Status | Meaning |
|---|---|
| `MIGRATED_VERIFIED` | An equivalent Rust test executed at the cited exact candidate (author-run unless independent evidence is separately named). This does not imply live, provider, browser, isolation or independent acceptance. |
| `MIGRATED_NOT_VERIFIED` | A meaningful Rust replacement exists, but the suite-level invariant, process E2E, or exact-candidate execution is incomplete or pending. |
| `NOT_IMPLEMENTED` | No Rust replacement test or behavior exists for the material invariant. |
| `BLOCKED` | Replacement cannot be verified because required isolation, provider lifecycle, authorization, budget or live evidence is unavailable. |
| `OBSOLETE_BY_DESIGN` | The legacy mechanism must not be ported (for example the Paseo intermediary or a side budget ledger), although its behavioral lessons remain. |
| `RETAINED` | The legacy suite/fixture is still applicable and must not be retired until a named replacement exists. |

## 11. Priority order for porting the remaining invariants

1. **Core-owned authorization, budgets and public dispatch with a fail-closed isolation gate.** Everything provider-backed or campaign-like is blocked on this. Keep `dispatch_supported=false` until then.
2. **Process-level Core/Worker restart, stale-generation fencing and durable outcome recovery.** Finish the pending `native/tests/e2e_core_recovery.rs` and extend it to Worker kill, lease expiry and receipt replay.
3. **Direct Codex/OpenCode work lifecycle:** prompt submission, progress/tools, permissions, terminal distinctions, cancel/timeout, reconnect and truthful cleanup. This must include fixture transcripts before any paid authorization.
4. **Sandbox and credential confinement:** verify the named-volume mount boundary, prove provider secrets stay outside the project process and independently verify isolation. Do not infer security from the Alpine fixture.
5. **Independent verifier/reviewer processes:** clean read-only checkout, frozen oracle execution including browser checks, exact-candidate receipts and a reachable deterministic gate.
6. **Campaign scheduler and WorkGraph:** frozen plan, dependency-aware dispatch, no double-claim, bounded repair, HUMAN_REQUIRED, cancellation and crash/restart recovery.
7. **Multi-project configuration and capabilities:** revisioned Project config, capability routing, Worker-managed browser test servers and cross-project isolation.
8. **Rust-backed Office and browser journeys:** rewire the retained React Office to Rust Core; port S1/S2/S3/S4 browser oracles plus reconnect, malformed-SSE and soak coverage.
9. **S4-D Lead persistence/activation and CAP-014:** only after ADR-0017 policy is ratified; keep autonomous start closed and preserve frozen corpus semantics in any new evaluation version.
10. **Live certification and budget tooling:** last; Core must own reservations. Retain the Python guards/validator only as governed tooling until a reviewed replacement exists.
