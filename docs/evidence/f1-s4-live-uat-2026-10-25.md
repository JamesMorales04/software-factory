## 8. Failures found and repaired

Every repair below is in the repair PR, and is covered by the cited test, the
Phase A disposable-script run, or the live journey. The script-cleanup repair
was exercised by the Phase A run; the provider, lease and finalize repairs were
exercised by the live journey:

1. Unsafe UAT cleanup: `pkill` by process name could kill unrelated
   Supervisors/Workers. The disposable script now stops only its private
   runtime and removes only its unique container/volume.
2. Core model-gateway and egress rejected the fixed OpenCode Go base path
   `/inference/go/openai/v1`. Both now validate a bounded fixed base path.
3. OpenCode Go requires `x-opencode-session`; Core model calls and provider
   egress now send/preserve a per-call/per-run session header.
4. OpenCode host bridge reused a half-closed connection for the next request.
   The OpenCode HTTP client now disables idle pooling; the provider bridge was
   wired for the real TCP provider.
5. Bun/OpenCode crashed with SIGILL under the 4 GiB address-space limit. The
   OpenCode sandbox default is now 16 GiB (configurable); fixture providers
   keep 4 GiB.
6. Provider API calls used the host session directory. Sandboxed providers now
   use `/session` while Core still records the host directory.
7. SSE validation treated a message `info.id` (`msg_*`) as a session identity
   contradiction. Only `session.*` events are compared.
8. The terminal wait allowed only 30 seconds and 256 SSE chunks. Real
   streaming needed 300 seconds/100,000 chunks; a high-volume regression test
   was added.
9. Empty `final` responses were accepted and then failed in the Supervisor.
   The Worker now corrects an empty final, refuses to finalize after no writes,
   and preserves applied writes after a turn-budget exhaustion or post-write
   provider error.
10. Supervisor finalize returned 500 for an unchanged worktree and left
    check-command workspaces `RUNNING`/`FAILED`, blocking finalization. The
    workspace now rejects empty commits explicitly and check-command errors
    keep the applied worktree available.
11. The Worker heartbeat ran every 20 seconds but extended the lease by only
    15 seconds, shortening a 60-second claim and letting the lease expire
    mid-session. Heartbeats now extend by 60 seconds, never shorten a lease,
    and run every 15 seconds; a regression test asserts no shortening.
12. The Reviewer request used a 4,096-token output cap; the real model returned
    empty content. It now requests 8,192 and the operator resolved the preserved
    UNKNOWN reservation before retrying on a new candidate.
13. The Lead model prompt omitted the generated schema and effort contract,
    producing three genuine model failures. The prompt now includes the schema,
    a valid example, hard identity/route/budget constraints, and the requirement
    that a change request carries an effort estimate.

- For `FACTORY_PROVIDER_KIND=opencode`, the Worker pre-prompt digest cannot
  describe the body OpenCode actually emits. The egress broker therefore
  computes SHA-256 of the exact emitted bytes and calls Core
  `/worker/provider_turn_bind` before forwarding. Core binds that digest to the
  live reservation, session, worker generation, lease, model, path and size;
  the broker also pins the model, endpoint, bearer capability, request count
  and turn policy. A request whose binding is refused is never forwarded. This
  is the actual-request contract that replaces the fixture-era pre-prompt
  digest comparison; it does not restore a check that would make OpenCode
  execution impossible. The broker no longer forwards a client-supplied
  `x-opencode-session`; it uses the broker's per-run session identity. It also
  rewrites `max_completion_tokens` in addition to `max_tokens`, applies a
  conservative 4-bytes-per-authorized-input-token body guard, and Core detects
  any remaining over-budget usage at settlement. `FAILED` provider terminals
  require a cleanup receipt (`no_external_session` is explicit).
