**REL-001 Wave 3 update (2026-11-03, candidate `54f6537`).** The recorded CI
flake in `db::provider_sessions::tests::execution_check_receipts_bind_the_frozen_command_and_candidate`
was attributed by inspection to a write-before-validation path plus SQLite's
deferred read-to-write transaction upgrade. Writer transactions now resolve
execution-check facts before writing, use `BEGIN IMMEDIATE`, and await rollback;
regressions cover rejected writes and ordered concurrent writers. The exact
interleaving was not reproduced locally, so the entry stays open pending
independent failure-injection and repeated clean-checkout stress evidence.

The register tracks product risks. Closing an entry requires a candidate-bound Action, evidence and independent review; it is not a substitute for the Quality Gate.
